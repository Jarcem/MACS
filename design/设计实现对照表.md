| 租约与 E01 重试双记账 | §6.4.3.1「唯一记账口径」 | `attempt_count` 仅由 `ClaimSubtask` 递增；租约到期复用 E01 `failed + next_retry_at` 退避，禁止直接置 `pending`；统一 `backoff(n)=min(2^(n-1)×5s,60s)`；`max_retries` 含首发；`failed` 带 `next_retry_at` 不判 `partial_failure`；复核子任务受租约保护但不重投 |
| 终态条件更新与复核状态机冲突 | §6.4.3.2 两条分支 SQL + 来源状态表 | 普通子任务仅 `dispatched/running` 且 `attempt_count>0`；复核子任务兼容 `pending`，但要求 `attempt_count=0` 且 `incubator_id` 为空/匹配，收口补记 attempt=1；所有内部状态回写（质量管线、dispatch 回滚）加 `status <> 'cancelled'` 门 |
| 取消墓碑不持久 + API 未入清单 + 收尾未定义 | §6.4.3.3、DB §3.13、附录 B.1 | 墓碑落本地 `cancel_tombstones`（24h、启动加载）；明确“墓碑非正确性唯一依赖”；补齐成本不回收/取消归档/审批作废/进度冻结/事件口径；API 返回 `changed` / `cancelled_subtasks` / `notified_incubators`，scope=ops |
| SSE 只有事件名无帧规范 | §6.4.13.4.1 | 响应头、`id/event/data` 行、15s 心跳、`Last-Event-ID` 回放 ≤200、`addEventListener` 强制、慢客户端 256 帧上限 |

**实现顺序**：attempt 唯一记账 → 租约回收 → 终态条件更新 → 取消中断与墓碑 → SSE 命名事件。设计已完备，实现状态仍以上表第一节为准。
